Workshop debrief

The session was about changing the shape of everyday work.

The useful shift is not from no AI to more AI. It is from casual prompting to a repeatable work system: clear tasks, durable knowledge, explicit instructions, visible prototypes, and review gates before AI output reaches a client or decision forum.

Prompting

Prompts are work contracts.

Role, task, context, examples, output format, and review criteria turn AI from an empty chat box into a governed collaborator.

Second brain

Useful knowledge should compound.

Codex can turn notes, links, decks, research, and decisions into a living memory layer that gets easier to query and maintain.

Prototype culture

Showing beats explaining.

Vibe coding is most valuable when it converts a vague workflow into something visible enough for users and stakeholders to critique.

Signal 01

AI belongs inside work products.

Decks, spreadsheets, documents, research notes, and prototypes are where adoption becomes measurable and habit-forming.

Signal 02

Structure is the new productivity layer.

Prompt libraries, SKILL.md files, AGENTS.md guidance, and second-brain pages make good work easier to repeat.

Signal 03

Governance decides whether AI scales.

Deloitte's 2026 AI research points to a familiar pattern: access is growing quickly, but governance and fluency decide whether value compounds.

How to use the learning

A practical AI operating system for the week after the workshop.

Each framework is short enough to use in a live workday, but specific enough to become a team habit. Start with one real deliverable, then capture the method as a reusable prompt, skill, or second-brain page.

Prompting ladder

Ask, improve the ask, then govern the output.

Use this when the task is ambiguous, high-value, or repeatable.

1

Name the work product.

Memo, tracker, slide outline, spreadsheet insight, prototype, code change, or meeting brief.

2

Add the operating context.

Audience, business goal, source material, constraints, sensitivity level, and deadline.

3

Define the output contract.

Format, length, tone, decision criteria, evidence requirements, and what must be excluded.

4

Review before reuse.

Ask for assumptions, missing evidence, weak logic, edge cases, and confidence flags.

Meta prompting

Use AI to design the prompt before doing the task.

Meta prompting is useful when the workflow will be repeated, delegated, audited, or taught to a team.

1

Prompt generator.

Ask AI to convert a rough task into a robust prompt with role, context, inputs, steps, and output format.

2

Prompt critic.

Ask what the prompt fails to specify: audience, examples, acceptance criteria, risk, or source boundaries.

3

Workflow translator.

Convert a human process into repeatable AI instructions: trigger, inputs, process, review, and final artifact.

4

Evaluator prompt.

Create a checklist or scoring rubric so every output can be reviewed the same way.

JSON prompting

Use structure when the output needs to move downstream.

JSON is not for every answer. It is for trackers, automations, tables, evaluations, and repeatable handoffs.

1

List fields first.

Define the exact keys, allowed values, and whether each field is required.

2

Describe the semantics.

Tell the model what each field means, not just what it is called.

3

Add one example.

Provide a tiny valid object so the model can mirror the shape and level of specificity.

4

Validate before trusting.

For production, use schema-based structured output or a parser rather than relying only on wording.

Second brain method

Move from stored files to compiled knowledge.

Use this to maintain a practical Codex knowledge base inspired by LLM wiki and GBrain patterns.

1

Capture sources.

Notes, reports, transcripts, links, decisions, meeting outputs, and reusable prompts.

2

Compile pages.

Turn raw material into short pages for concepts, clients, sectors, workstreams, and methods.

3

Link the system.

Connect pages with relationships such as affects, supports, updates, contradicts, and owner.

4

Review weekly.

Ask Codex to find stale claims, contradictions, missing links, orphan pages, and useful updates.

AI for work products

Accelerate decks, documents, and spreadsheets.

Use AI for structure, critique, cleanup, and first-pass synthesis, not as the final owner of judgment.

1

Presentation.

Start with a decision memo, convert it to storyline, then create slide titles, evidence, and visual suggestions.

2

Documentation.

Convert transcripts into decisions, actions, risks, FAQ, standard operating notes, and follow-up emails.

3

Excel.

Profile data, explain formulas, identify outliers, draft checks, and translate analysis into executive insight.

4

Quality control.

Check formulas, source references, chart labels, definitions, and whether the conclusion follows the evidence.

Skill files

Package a repeated workflow as instructions.

A SKILL.md file makes quality portable across future Codex sessions and across teams.

1

Define trigger conditions.

When should the skill be used, when should it not be used, and what words should trigger it?

2

Write the workflow.

Inputs, steps, checks, expected artifacts, safety boundaries, and what to do when information is missing.

3

Attach references.

Add templates, examples, schemas, and quality criteria so the skill improves the next run.

4

Test the trigger.

Ask Codex what skill it would use for sample tasks and tighten the description if it misfires.

Vibe coding

Prototype the workflow before debating it.

Use this when a team can learn faster from a clickable artifact than from a long explanation.

1

Choose one workflow.

Pick a painful repeat task, not a vague AI ambition.

2

Mock the happy path.

Build the smallest useful screen, form, dashboard, or generator that makes the idea tangible.

3

Test with users.

Watch where people hesitate, what they ask to change, and what they would trust.

4

Decide the next step.

Retire it, improve it, or turn it into a governed pilot with owners, data, controls, and metrics.

AI governance habit

Scale use cases with controls, not wishful thinking.

Use this for client-facing, regulated, confidential, or operational AI workflows.

1

Classify the use case.

Personal productivity, team workflow, client deliverable, regulated process, or autonomous action.

2

Set data boundaries.

Define what can be pasted, what must be masked, and what must stay inside approved systems.

3

Retain evidence.

Keep source links, assumptions, human approvals, and versioned outputs for auditability.

4

Assign human ownership.

Every AI-assisted deliverable needs a reviewer who owns correctness, tone, and risk.
