Six-step setup

From scattered notes to a living system.

The goal is not to store more material. The goal is to make useful synthesis easier to find, reuse, and improve after every real assignment.

01

Open a workspace

Create a Codex folder for one domain, team, client issue, or personal workflow. Keep the scope narrow enough to maintain.

02

Create the map

Add folders for raw sources, wiki pages, prompts, decisions, runs, templates, and reading notes.

03

Seed sources

Drop in workshop notes, public reports, meeting summaries, spreadsheets, and useful links. Do not mix in confidential material unless approved.

04

Compile pages

Ask Codex to create concise wiki pages for entities, concepts, issues, decisions, and reusable methods.

05

Add prompts

Turn repeated requests into named prompts with inputs, rules, output schema, and a quality gate.

06

Review weekly

Ask Codex to find stale claims, missing links, contradictions, and high-value updates. Promote only what survives human review.

Reference pattern

Karpathy LLM Wiki plus Garry Tan GBrain.

The practical takeaway is simple: do not make AI reread everything from scratch. Let it maintain a durable, readable knowledge layer that people can inspect.

LLM Wiki

Compile knowledge into pages.

Keep immutable raw sources, update wiki pages, add cross-links, and run lint checks for stale or contradictory claims.

GBrain

Make the brain operational.

Use typed links, source registers, recurring jobs, and skills so the knowledge base supports real workflows rather than passive storage.

Prompting and meta prompting

Prompting is task design, not magic wording

Good prompts define the role, context, constraints, workflow, output format, and quality gate. Meta prompting makes the model improve the prompt before doing the work.

RoleWho should the model act as?
RulesWhat must it do, avoid, and verify?
ShapeWhat output structure is useful?

Meta prompting types

                
Ask the model to improve the ask.

              

              
Meta prompts are useful when the first request is vague, high-stakes, repeated, or needs a consistent format across a team.

            

            

              

                Prompt refiner
                
Turn messy intent into a strong prompt.

                
Ask for missing context, assumptions, better wording, constraints, and an output schema before execution.

              

              

                Rubric creator
                
Define how quality will be judged.

                
Have the model create a scoring rubric, then use that rubric to review its own draft and propose fixes.

              

              

                Expert panel
                
Generate multiple lenses.

                
Ask strategy, risk, data, legal, and change experts to critique the same work before producing the final output.

              

              

                Clarifying questions
                
Ask before answering.

                
Force the model to ask only questions that would materially change the answer, then proceed with stated assumptions.

              

              

                Output architect
                
Design the deliverable structure.

                
Ask the model to choose the best format: memo, table, slide outline, JSON, checklist, tracker, or storyboard.

              

              

                Red-team prompt
                
Find weak claims before sharing.

                
Ask for unsupported assumptions, ambiguous wording, confidentiality risks, and missing evidence.

              

            

          


          

            

              

                
JSON prompting

                
Use JSON when outputs need to be reused.

              

              
JSON prompts are valuable for structured extraction, batch processing, image briefs, spreadsheet cleanup, evals, dashboards, and any output another tool should read reliably.

            

            

              

                

                  Extraction
                  
Actions, owners, dates, risks.

                  
Get clean fields from messy notes without losing an assumption log.

                

                

                  Content generation
                  
Consistent sections at scale.

                  
Generate slide titles, chart notes, executive summaries, and quality flags in a stable shape.

                

                

                  Image and design
                  
Control composition.

                  
Specify subject, style, constraints, format, negative prompts, and quality checks.

                

              

              
{
  "role": "Deloitte India engagement manager",
  "task": "Extract meeting decisions and actions",
  "input": {
    "meeting_context": "<client, date, workstream>",
    "notes": "<<<paste notes>>>"
  },
  "rules": [
    "Do not invent owners or due dates",
    "Separate facts from assumptions",
    "Flag confidential or personal data"
  ],
  "output_schema": {
    "summary": "string",
    "decisions": [{"decision": "string", "rationale": "string"}],
    "actions": [{"action": "string", "owner": "string", "due_date": "string"}],
    "open_questions": ["string"]
  }
}

What to prototype

                
Build the smallest artifact that proves the workflow.

              

              
Do not start with production engineering. Start with a credible interaction that reveals data needs, user behavior, risks, and decision value.

            

            

              

                Client workshop demo
                
Show the future workflow.

                
Mock the dashboard, assistant, tracker, or briefing flow using sample data and realistic outputs.

              

              

                Internal productivity tool
                
Automate a repeated task.

                
Prototype a summarizer, deck reviewer, risk scanner, or spreadsheet profiler before writing a business case.

              

              

                Applied AI lab asset
                
Create reusable capability.

                
Convert promising prototypes into demoable assets, prompt packs, and implementation playbooks.

              

            

          


          

            

              

                
Prototype prompt

                
A starter brief for Codex.

              

              
Use this when you want a pure front-end prototype with no backend dependency.

            

            
You are Codex, acting as a senior product engineer and designer.

Build a pure front-end prototype for this workflow:
<describe user, problem, and desired outcome>

Constraints:
- No backend. Use static HTML, CSS, and JavaScript.
- Use mock data that looks realistic but contains no confidential information.
- Make the first screen the actual working experience, not a marketing page.
- Include states for empty, loading, success, and review-needed where relevant.
- Use Deloitte-inspired black, white, neutral, and green styling with restrained data accents.
- Add comments only where the code is not self-explanatory.

Before finalizing:
- Verify desktop and mobile layout.
- Check that text does not overflow.
- Explain what is implemented, what is mocked, and what would be needed for production.
