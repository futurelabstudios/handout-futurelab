The brief

The workshop's central message: AI adoption becomes real when teams turn tools into repeatable, governed work systems.

Debrief

This is the move: from AI as a side tab to AI as operating infrastructure.

For Deloitte USI, the adoption question is not "which tool should I try?" It is "which recurring workflow can become more consistent, traceable, and decision-ready when AI has the right context?"

1
Prompt like a manager.

Give role, context, evidence, output format, constraints, and review criteria.

2
Make knowledge reusable.

Meeting notes, workpapers, links, reports, decisions, and prompts should compound into a living system.

3
Measure value through prototypes.

A small artifact reveals source gaps, adoption friction, control issues, and the business case.

Recommended next move

Pick one workflow. Build the assistant around the work. Prove the delta.

Start narrow: one process, one user group, one output standard, one review gate, one measurable before-after comparison.

Management lens

What should change after the workshop

From prompts to playbooksCapture the best way to ask, review, and reuse a task so quality does not depend on memory.
From files to knowledge systemsLet source documents, notes, decisions, and links become queryable institutional memory.
From demos to controlled prototypesBuild small AI workflows with named owners, evidence trails, and clear review gates.
From speed to trustPreserve source quality, confidentiality, control totals, exception logic, and human accountability.

Mental models

The useful shift is to treat prompting, structure, and review as management disciplines, not writing tricks.

Mental model 01

Contextual prompting: from request to work contract

Naive prompt

"Summarize this."

Expert prompt

"You are a consulting manager preparing a board-level synthesis. Focus on strategic implications, differentiation, evidence quality, and executive readability."

The difference is not eloquence. It is role, context, audience, sources, constraints, format, and acceptance criteria.

Mental model 02

Engines versus vehicles

E
LLMs are engines.

Models provide reasoning, language, code, retrieval, and generation capability.

V
Apps are vehicles.

Codex, NotebookLM, ChatGPT, Claude, Perplexity, and internal tools package capability into workflows.

Prompting stack

The five layers that make AI output usable

1
Role and task

Who should the model behave as, and what decision or artifact should it produce?

2
Context and source material

What files, notes, policies, data definitions, examples, or constraints should govern the answer?

3
Output structure

Ask for a table, checklist, JSON object, slide outline, memo, or procedure so the result can be reused.

4
Review criteria

Tell the model what good looks like: accuracy, evidence, executive clarity, risks, and next actions.

5
Iteration loop

Ask the model to critique, improve, and expose assumptions before the human signs off.

JSON prompting

Use structure when AI output becomes input.

JSON prompting is useful when the result must flow into spreadsheets, trackers, apps, QA checklists, or downstream automation.

The second brain

A Deloitte second brain should be source-backed, skill-guided, continuously refreshed, and easy to interrogate through AI.

Core principle

Build the brain before you ask the agent.

The agent becomes useful when it has a stable operating manual, source-backed memory, and a refresh loop. Without that, every chat begins from scratch.

Karpathy lens

Distill what should survive into wiki-like pages: decisions, lessons, preferences, project context, and reusable notes.

Garry Tan lens

Treat the brain as a system of record: markdown pages, typed links, search, and a repo/database that can be updated over time.

Build method

A simple second-brain build sequence.

01

Create the SKILL.md first

Define the role, scope, source rules, confidentiality constraints, output formats, examples, and review gates before loading knowledge.

02

Connect the source map

Point the system to approved notes, PDFs, decks, workpapers, policies, prompts, decisions, and links. Keep raw sources separate from distilled pages.

03

Distill into wiki pages

Create living pages for people, projects, processes, risks, decisions, definitions, and reusable methods so the model can retrieve the right context.

04

Create the refresh pipeline

On a cadence, ingest new material, deduplicate, update stale pages, preserve source trails, and mark what needs human approval.

05

Attach the brain to an AI interface

Use Codex or another approved AI surface to ask questions, generate outputs, and write validated learning back into the brain.

What goes inside SKILL.md

The skill file is the operating manual.

R
Role

What kind of Deloitte expert should the AI behave like?

S
Sources

Which folders, links, templates, and artifacts are trusted?

O
Outputs

What should the AI produce: memo, slide outline, JSON, table, checklist, sample, or code?

Q
Quality gates

What must be checked before the output is used: source trail, logic, confidentiality, owner, and assumptions?

Governance lens

Make the brain useful, but evidence-aware.

For Deloitte work, the second brain should not hide uncertainty. It should show source files, extract dates, assumptions, control totals where relevant, exception criteria, and the human who approved the knowledge.

Applied AI Lab

AI feels concrete when a team can touch a prototype, test the workflow, and decide whether to promote it.

Prototype agenda

Build prototypes that make AI value observable.

The Applied AI Lab should turn abstract AI interest into tested workflows: who uses it, what source data it touches, what it produces, what review gate exists, and how value is measured.

Audit data profiler Controls evidence agent Excel analyst Presentation builder Meeting-to-deliverables agent

Build discipline

Prototype before debating. Govern before scaling.

A good prototype is small enough to build quickly and serious enough to expose trust, evidence, ownership, and adoption issues.

Work-product playbook

High-value places to apply AI this week

PresentationsConvert analysis into storyline, slide titles, executive messages, exhibits, and speaker notes.
DocumentationTurn meetings into decisions, risks, action logs, FAQs, SOP drafts, and review-ready summaries.
SpreadsheetsExplain formulas, profile data, flag outliers, draft checks, and convert tables into decision insight.
Prototype appsBuild thin workflow tools that test role clarity, input quality, output usefulness, and review gates.

Audit and data lens

When AI touches data, make the evidence trail visible.

1
Preserve source files

Keep raw extracts read-only and record file names, dates, row counts, and sheet names.

2
Profile before testing

Identify keys, nulls, duplicates, amount/date fields, ranges, and obvious quality flags.

3
Reconcile and explain

Tie filtered populations back to control totals and document thresholds, exclusions, and exceptions.
